# 录音自动转写 1.4.5（versionCode 24，后台队列修复候选）

这是给 ColorOS 录音机使用的 LSPosed 模块。模块调用录音机和 AI 语音摘记服务处理转写与摘要，不提供独立 AI，也不改变原应用的账号、协议、网络或服务配额。1.4.5 修复周期任务过早结束的问题，并把任务登记、任务启动、桥接就绪、扫描尝试、扫描快照保存和扫描失败分开记录。目标设备已安装并报告一次扫描快照成功；冷进程 JobScheduler 唤醒和原服务结果落库仍未验收。

## 1.4.5 处理规则

- 首次安装时自动处理默认关闭。用户主动开启后模块才会扫描并提交待处理记录。
- 管理页只以录音机本地数据库中的录音为准，不创建、同步或导出独立的录音、转写或摘要副本。摘要仍保存在录音机数据库，没有独立的摘要文件路径。
- 转写最多同时处理 3 条；AI 摘要最多同时处理 1 条。
- 录音机 16.17.8 的设置页提供“录音自动转写”入口，打开模块管理页；模块仍须单独安装并在 LSPosed 启用。
- 后台入口继续复用录音机自身的 15 分钟周期 Job，不添加常驻前台服务、精确闹钟或 Wi-Fi／充电约束。JobService 会等到扫描快照写入后再结束任务；重复唤醒合并处理。Android/Oplus 仍可能延后任务。
- Android 重启后，Job 不依赖系统跨重启保留；按设计在用户首次打开录音机时重新登记。没有开机接收器，因此不承诺重启后在用户打开录音机前自动恢复。
- 管理页分别显示周期任务登记、最近任务启动、桥接就绪、最近队列检查、最近成功并保存的扫描时间及失败原因。周期任务登记成功不代表扫描成功；摘要只有在原录音机数据库出现保存记录后才计为完成。
- 文件未变化且转写、摘要都已完成的条目，在同一录音机进程中最多 1 小时复用已核实状态，之后重新核对。打开管理页只读取状态，手动按钮用于立即检查。
- 原服务返回 `100013` 时显示“文本不足 100 字，原服务已跳过”，不自动反复提交摘要。
- 重启后若无法从录音机数据库确认某条摘要的最终状态，模块不会自动重交，以免重复生成。长期无法核实时，列表提供“确认重新生成摘要”；只有用户明确确认后才清除旧等待状态。

## 安装与启用

目标设备、签名和验证证据见[设备验证记录](outputs/device-validation-2026-09-26.md)。1.4.5 的单元测试和签名候选构建通过；设备状态页报告扫描快照在 08:54 保存，专项冷进程触发没有观察到新的 Job 启动。真实转写/摘要落库也未确认，酷安说明继续保持草案状态。

在 LSPosed 启用模块，并同时勾选两个作用域：

- `com.coloros.soundrecorder`（录音）
- `com.coloros.accessibilityassistant`（AI 语音摘记／无障碍助手）

安装、更新或修改作用域后，应重启上述两个应用进程。首次使用还需按录音机提示确认转写服务协议；这不替代模块内对自动处理的确认。

## 兼容范围

当前只对以下组合进行适配：

- ColorOS 录音机 16.17.8
- AI 语音摘记／无障碍助手 16.3.12
- Android 16
- Root + LSPosed

其他录音机、助手、Android 或 LSPosed 环境未作兼容承诺。
